# 4주차 - 셸 스크립트와 백업 자동화

## 저장소에 있는 실습 코드

[backup.sh](./backup.sh)는 폴더를 tar.gz로 압축하고 성공한 백업의 일시와 파일명을 `backups/backup.log`에 기록한다. [기존 PR #1](https://github.com/thingjae85/devops/pull/1)에서 로그 기능이 Merge된 것을 확인할 수 있다.

## 코드 흐름을 내 말로 설명

1. 스크립트가 있는 폴더로 이동한다. 어느 위치에서 실행해도 같은 기준 경로를 쓰기 위해서다.
2. 첫 번째 인자를 원본 폴더로 사용하고, 인자가 없으면 `test`를 사용한다.
3. 원본 폴더가 없으면 종료 코드 1로 실패를 알린다.
4. `mkdir -p`로 백업 폴더를 준비하고 `tar -czf`로 압축한다.
5. 바로 직전 명령의 종료 코드인 `$?`를 확인해 성공과 실패를 나눈다.
6. 성공하면 크기와 목록을 보여 주고 `>>`로 로그 끝에 기록을 덧붙인다.

## 주요 문법

| 문법 | 이 코드에서 하는 일 |
|---|---|
| `${1:-test}` | 첫 번째 인자가 없을 때 기본값 사용 |
| `$(date ...)` | 명령의 출력값을 변수에 저장 |
| `$$` | 현재 셸 PID를 파일명에 넣어 이름 충돌 가능성 줄이기 |
| `[ ! -d "$SOURCE_DIR" ]` | 원본 디렉터리가 없는지 검사 |
| `exit 1` | 실패를 호출한 쪽에 전달 |
| `>>` | 기존 로그를 덮어쓰지 않고 뒤에 추가 |

## 재현 명령

아래 명령은 저장소 코드의 사용 방법이다. 새 실행 결과를 측정한 기록은 아니다.

```bash
cd ~/devops/week04
bash backup.sh test
ls -lh backups
cat backups/backup.log
# 복원 가능한지 별도 폴더에서 확인
mkdir -p restore-check
tar -tzf backups/<생성된_백업파일>.tar.gz
tar -xzf backups/<생성된_백업파일>.tar.gz -C restore-check
```

백업 파일이 생겼다는 사실만으로는 충분하지 않다. 압축 안에 원본 파일이 들어 있고 다시 풀리는지도 확인해야 한다. 반복 작업을 스크립트로 적어 두면 같은 절차를 다시 실행할 수 있고, 로그를 통해 언제 무엇을 했는지 확인할 수 있다.
